
# Guia de Contribuição — PortfolioHUB

## 1. Apresentação

Este documento estabelece as práticas de colaboração,
compartilhamento e controle de versões do PortfolioHUB.

**Autor:** Vitor Andrade de Moura  
**Disciplina:** Bootcamp I  
**Projeto:** PortfolioHUB + IA Gemini

## 2. Organização do Projeto

O PortfolioHUB utiliza Git e GitHub para armazenar
arquivos, registrar alterações e compartilhar
os projetos acadêmicos.

O repositório é público para consulta,
mas a modificação direta dos arquivos
é restrita aos usuários autorizados.

## 3. Controle de Versões

O projeto utiliza Git para acompanhar
seu histórico de desenvolvimento.

A branch principal é denominada `main`.

A versão inicial foi registrada com a tag `v1.0`.

As alterações posteriores são documentadas
por meio de commits.

## 4. Procedimento de Contribuição

Para propor uma alteração no projeto:

1. Consultar a documentação existente.
2. Criar uma branch específica para a alteração.
3. Implementar as modificações necessárias.
4. Testar o funcionamento dos arquivos.
5. Registrar as alterações em um commit.
6. Enviar a branch ao GitHub.
7. Abrir um Pull Request para revisão.
8. Integrar a alteração após aprovação.

Este procedimento representa o fluxo recomendado
para futuras contribuições.

## 5. Padrão de Commits

As mensagens devem descrever
claramente as alterações realizadas.

Exemplos:

- `docs: atualizar documentacao`
- `feat: adicionar nova funcionalidade`
- `fix: corrigir erro no site`
- `style: melhorar aparencia do portfolio`
- `security: atualizar configuracoes de seguranca`

## 6. Gestão de Acesso

O proprietário do repositório é `nuss44`.

Durante a verificação de segurança,
não foram identificados colaboradores externos.

Novos colaboradores deverão ser autorizados
pelo proprietário antes de receber acesso.

## 7. Segurança

Não devem ser publicados:

- Senhas e credenciais.
- Tokens de acesso.
- Chaves privadas de API.
- Arquivos contendo informações pessoais sensíveis.

O arquivo `.gitignore` auxilia na prevenção
do versionamento acidental de arquivos locais.

## 8. Revisão de Alterações

As alterações deverão ser verificadas
antes de sua integração à branch principal.

A regra `Protecao_Branch_Main` foi configurada
com opções para restringir exclusões e
bloquear envios forçados.

A aplicação efetiva dessas restrições
depende das condições do plano GitHub.
